# Киомей — сайт для партнёров

Четыре формата единого бренда: японское бистро, точка рамена, точка суши, точка матча моти. Главная, страницы концепций, PDF-презентации, интерактивная модель и защищённый редактор.

Публичный сайт: https://kyomei-partners-roman.kruasanov.chatgpt.site

## Страницы

- `/` — главная и варианты участия.
- `/concepts/bistro`, `/concepts/ramen`, `/concepts/sushi`, `/concepts/matcha` — форматы.
- `/model?format=ramen` — экономика; параметр `mode=passive` выбирает фиксированную ставку.
- `/admin` — информационное меню, цены и доступность по часам; средний чек, фудкост, планы продаж, расходы и условия участия.

## Запуск полного проекта

Нужны Node.js 22.13+ и npm. Рекомендуется Node.js 24.

```sh
npm run install:ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_faithful_wendell_rand.sql
npm run dev -- --port 8787
```

Откройте http://127.0.0.1:8787. Миграцию при первой настройке выполните один раз. Локальные записи хранятся в `.wrangler/state`, рабочие — в базе опубликованного сайта.

Пароль не хранится в репозитории. Для локального редактора задайте `ADMIN_PASSWORD_HASH` в игнорируемом `.dev.vars` в формате `pbkdf2$100000$salt$hash`. Скрипт `scripts/admin-password.mjs` принимает пароль через стандартный ввод и выдаёт значение для этой переменной. `SITE_ORIGIN` — адрес сайта без завершающего слеша. На опубликованном сайте оба значения заданы серверными переменными окружения.

## Настройки и расчёт

`data/default-config.json` — точный снимок утверждённых пользователем настроек опубликованного сайта: версия 32 от 1 ноября 2026, 19:00 по Москве. Метаданные источника и контрольная сумма — `data/baseline-metadata.json`. Снимок содержит весь каталог, меню и все параметры четырёх форматов. Это закреплённая база для возврата; обычное сохранение админки её не изменяет.

API возвращает текущую конфигурацию из D1 и отдельный объект `baseline` с сохранённой базой. Если база D1 пуста, текущими значениями становятся базовые. Сама публикация исходников не перезаписывает существующие настройки D1.

В админке «Вернуть базовые настройки» после подтверждения загружает все четыре формата и каталог только в черновик. Общие значения обновятся лишь после обычного «Сохранить» с проверкой версии. Отмена оставляет черновик без изменений. Экспорт черновика по-прежнему доступен.

В модели «Вернуть базовый сценарий» локально восстанавливает весь выбранный формат: оба типа дня, чек, фудкост, обслуживание, меню, расходы, календарь и условия участия. Остальные сценарии сохраняются. При отличиях от актуальных настроек команды можно переключиться обратно. Ни один из этих действий инвестора не записывает данные на сервер.

Одна продажа — **один чек**, оплаченный заказ с любым количеством блюд. Меню полностью информационное: его изменение не меняет выручку, фудкост, мощность и точку нуля.

В `format.check` отдельно задаются средний чек, общий фудкост и средняя упаковка на чек. Инвестор меняет средний чек (рубли) и фудкост (проценты) в своём сценарии; общие настройки не перезаписываются. Утверждённая база: бистро 2400 ₽ / 30%; рамен 890 ₽ / 30%; суши 1190 ₽ / 33%; матча моти 690 ₽ / 35%. Это не отчётность действующего бистро.

Периоды: 10–12, 12–16, 16–20, 20–23; будни и выходные настраиваются отдельно. Спрос и мощность — чеки/час. Выручка = выполненные чеки × средний чек. Продукты = выручка × фудкост / 100. При нулевом спросе постоянные расходы сохраняются; при неположительной марже нет конечной точки нуля.

В бистро режим обслуживания меняет расходы на официантов. **Две хостес в смену остаются в обоих режимах**: 2 × полная ставка смены × рабочие дни. При включённом обслуживании добавляются официанты за месяц. Базовые расходы не должны повторять эти статьи. Средний чек и мощность автоматически от переключателя не меняются.

`lib/config-migration.ts` поднимает сохранённую версию 1 до версии 2, сохраняя меню, цены, аренду и планы. Старый расход зала бистро разделяется между двумя хостес и официантами. После сохранения админки в базу записывается v2. Арендные пределы в предложении — до 800 тыс. ₽ для бистро и до 500 тыс. ₽ для точек; расходы конкретной локации по-прежнему задаются в админке.

Партнёрский и фиксированный варианты считаются отдельно. Показатель «Прибыль после расходов и налогов» вычитает все заданные расходы и налог бизнеса. Активная выплата — доля положительной прибыли; модель предполагает распределение всей этой прибыли, без дополнительных удержаний в бизнесе. Для фиксированной ставки показаны покрытие прибылью и возможный дефицит. Личные налоги в обоих вариантах оплачивает инвестор. Налог бизнеса включён в расходы как допущение.

## Источники

183 позиции каталога: актуальное PDF-меню, официальные напитки, дополнительные позиции учебного меню и проектные порции/комбо. Позиции без подтверждённой цены выключены. Источник каждой позиции виден в редакторе. Подробности: `data/menu-provenance.txt`, `data/photo-provenance.json`.

Фотографии блюд — Киомей. Визуализации новых точек обозначены как концепции. Jost Regular и Medium размещены локально; лицензия в `public/fonts/Jost-OFL.txt`. Общий логознак и четыре палитры сохранены из согласованного пакета.

## Проверки

```sh
node --test tests/model.test.mjs tests/model-defaults.test.mjs tests/config-migration.test.mjs tests/baseline.test.mjs
node node_modules/typescript/bin/tsc --noEmit
```

`tests/api-smoke.mjs` принимает пароль через stdin и проверяет авторизацию, защиту от другого источника, валидацию, общее сохранение, конфликт версий и выход. На время проверки изменяет одну настройку, затем восстанавливает её. Используйте сначала локальную среду.

## Публикация и HTML-копия

Исходники — в GitHub, работающий сайт с серверной админкой — в Sites/Cloudflare Workers + D1. GitHub Pages сам по себе не исполняет серверную админку. Секреты и локальная база исключены из Git.

`scripts/export-html.mjs` создаёт отдельную HTML-копию для локального просмотра из работающей production-сборки. Она содержит главную, четыре концепции, модель и PDF. Редактирование общих данных открывается на публичном сайте; локальная HTML-копия использует снимок настроек на момент экспорта.
